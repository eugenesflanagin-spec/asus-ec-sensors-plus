**asus-ec-sensors-plus 0.1.2: bank switching on automatically where it is needed.**

0.1.1 added an optional `bank_switch=1` so the sensors stop going N/A on the
TUF GAMING X870-PRO WIFI7 W NEO (its BIOS firmware often leaves the embedded
controller on another register bank for minutes). In 0.1.2 that is the
default on that board, and stays off everywhere else.

### `bank_switch` values
| Value | Meaning |
|---|---|
| `-1` or `auto` (**default**) | on for boards flagged as needing it (so far only the TUF GAMING X870-PRO WIFI7 W NEO), off for all others |
| `0` (`n`, `N`, `off`) | never write to the EC (strictly read-only) |
| `1` (`y`, `Y`, `on`) | always on, same as 0.1.1 |

Any other value is refused and the module does not load. Existing
`/etc/modprobe.d` files with `bank_switch=1` keep working. The sysfs file
`/sys/module/asus_ec_sensors/parameters/bank_switch` now shows `-1`/`0`/`1`
instead of `Y`/`N`, and the kernel log says which mode was chosen.

"On" means, for each poll and under the firmware's ACPI lock: save the bank
register `0xFF`, set it to 0, read the sensors, write the saved value back.
**No other register is ever written** - no fans, PWM, voltages or settings.

**Behaviour change:** on the TUF GAMING X870-PRO WIFI7 W NEO the default is
no longer strictly read-only. Set `bank_switch=0` if you want that.

### Tested (BIOS 1805, Ryzen 7 7800X3D, 2026-10-26)
| Mode | Polls (1 s apart) | N/A |
|---|---|---|
| `bank_switch=0` (control; EC was on another bank) | 20 | 20 |
| `bank_switch=1` | 120 | 0 |
| default `auto` | 120 | 0 |

CPU Package vs. k10temp Tctl: mean -0.5 °C in both modes. Invalid values
(`2`, `-2`, `abc`) refused; kernel log clean.

### Install (Arch)
```
sudo pacman -U asus-ec-sensors-plus-dkms-0.1.2-1-any.pkg.tar.zst
sudo modprobe -r asus_ec_sensors; sudo modprobe asus_ec_sensors
sensors 'asusec-*'
```
